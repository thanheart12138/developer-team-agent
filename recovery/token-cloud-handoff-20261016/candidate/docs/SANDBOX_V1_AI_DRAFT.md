## 状态与范围

2026-10-08，AI 起草，用户已明确确认本文接口、状态及验收契约并授权实施，当前有效；2026-10-09 已实现及真实工具验证，模型自主返修未验证。继承 [已确认的执行隔离边界](REPAIR_DOCKER_ISOLATION_V1_AI_DRAFT.md) ，不替代其资源限制、探针或启用条件。

目标：为本项目已有原生网站提供统一的隔离测试能力，使开发自测和提交验证都经过同一边界。成功标准是程序能以固定接口执行真实 Node／HTTP／Chromium，阻断任务外文件、凭据、宿主网络及其他任务，并能在超时和恢复时留下可核对结果。

首版只支持已有原生网站的测试与验证。认证、模型调用、预算、产品修改、任务状态、独立目标审查仍属于宿主；网页预览仍由可信宿主静态服务提供。用户浏览器执行的 JavaScript 不在本 sandbox 的隔离范围内。

## 架构与职责

| 部分 | 职责 |
|---|---|
| Worker／开发工具 | 请求当前产品自测或已提交版本验证，依据实际结果执行原完成门禁 |
| SandboxRuntime | 绑定任务／尝试／版本，准备冻结快照，校验执行动作，管理生命周期、超时和宿主证据 |
| ContainerExecutionRuntime | 首版唯一底层实现，管理 Docker 镜像、容器、参数和实际配置核对 |
| SnapshotPreview | 提供同一冻结版本的本机静态预览及稳定 origin，不运行生成服务脚本 |
| Provider／目标审查 | 使用原宿主认证、请求守卫、独立审查和人工验收，不把 sandbox 成功当交付完成 |

调用关系：开发自测／固定验证 → SandboxRuntime → ContainerExecutionRuntime → 专用容器。结果经 SandboxRuntime 写宿主证据，再返回业务流程。业务流程不构造 Docker 参数、不接收模型 shell、不直接调用容器底层。

首版是本进程内部模块，复用现有 Runner 和快照实现。只保留一个 Docker 实现，不增加多后端插件、独立 HTTP 服务或额外调度系统。

## Dev Design：统一接口

拟在现有 `backend/app/runtime/` 增加 `sandbox.py`，不新增数据库表。接口只由可信程序调用，不直接注册为模型工具。

程序记录存于任务 `evidence/sandbox-<sandbox_id>/`：`runtime.json` 保存 facade 身份与生命周期，底层 `container.json` 和 `command-<id>.json` 保存容器及动作证据；完整接口结果另存 `result-<id>.json`。快照仍使用 `isolation/<attempt_id>/snapshots/<version_id>/product/`，以上目录均由宿主创建、不挂载给容器。

| 接口 | 输入 | 输出与语义 |
|---|---|---|
| `create(task_id, attempt_id, source_version)` | 程序绑定的任务、尝试及源产品清单哈希 | 冻结副本、核对源版本和实际容器配置；返回 `sandbox_id`、`version_id`、内部地址及证据引用 |
| `execute(sandbox_id, command_id, action, test_paths)` | 固定动作和程序核对的相对测试路径 | 有界实际结果与宿主证据；动作限定 `run_unit_tests`、`health_check`、`run_browser_validation` |
| `inspect(sandbox_id, command_id)` | 已登记身份及可选命令 ID | 实际生命周期、配置适用性、已保存结果或未知结果；只查询，不重放 |
| `stop(sandbox_id)` | 已登记身份 | 核对完整容器 ID、标签、镜像、快照后停止本 sandbox 全部后代；保留现场 |

路径、镜像、挂载、环境、网络、资源限额及超时来自宿主有效设计，不允许调用者任意覆盖。`test_paths` 仅用于 Node，必须在冻结产品中、不能是开关或快照外路径；浏览器动作固定执行 `verify_product.py`，传入容器内部 URL。

`sandbox_id` 由程序生成，绑定 task／attempt／version。`version_id` 绑定快照内容；需求、授权等完整提交版本仍由原提交协议绑定，不能用产品哈希代替完整提交。自测冻结当前产品，测试前后核对源版本；正式验证绑定显式提交。同版本可复用已经核对的快照，版本变化创建新的 sandbox，不覆盖旧证据。

## 生命周期、结果和恢复

宿主记录状态 `preparing` → `running` → `stopped`；准备或执行的副作用无法确认时进入 `unknown` 并停止流程。创建失败保留意图和环境错误，不自动回退到宿主执行。容器启动前检查实际配置；服务就绪由 `health_check` 确认，`running` 不代表服务、测试或业务已通过。

每条命令结果至少包含：sandbox／task／attempt／version／command ID、执行动作、镜像 ID／配置指纹、起止时间、实际退出码、超时事实、可确认的 OOM／资源事件、stdout／stderr 截断标记及宿主证据引用。尚不能确认的字段明确为空，不推测 OOM。

宿主记录执行意图先于副作用。相同身份、版本、配置及命令参数的完整宿主结果可以复用；只有意图而无结果时返回 `unknown_side_effect`，不得重新执行。恢复还须核对实际容器，身份不符或缺失明确停止；生成脚本输出不能修改宿主状态、预算或恢复依据。

Node／浏览器正常执行但断言失败交还原开发流程；缺镜像、Docker 异常、浏览器运行环境不兼容、超时、资源耗尽及未知副作用记环境停止，不默认要求模型改业务。exit 0、伪造成功文案、零测试、skip／todo、截断输出不能绕过现行完成门禁。

超时停止本 sandbox 全部后代，核对停止结果并记录；停止失败属于环境错误，不能声称清理成功。停止不删除容器、快照或证据，删除仍须另行授权。

## 验收与启用

1．正常路径：通过统一接口执行合成网站真实 Node 测试、内部 HTTP 和非 root 沙箱 Chromium；实际页面覆盖无效输入、错误后继续操作及刷新持久化。
2．隔离路径：任务外哨兵、其他任务、治理文件、凭据、Docker socket 均不可读；产品不可写，只有容量受限临时区域可写；外网、宿主服务和其他容器不可达，内部回环可用。
3．控制路径：实际 CPU／内存／PID／临时空间限额、超时停止后代、资源故障分类、结果有界及完整宿主证据可核对。
4．恢复路径：已知命令结果复用；未知结果、错误身份、版本或控制配置不符明确停止，不重复执行。
5．集成路径：新模式开发自测与提交固定验证均使用 SandboxRuntime；底层不可用时不回退宿主。保留源版本、显式提交、独立目标审查和人工验收门禁；旧任务不迁移。
6．预览路径：内部验证和外部预览绑定同提交；同 origin 更新／重启保持 localStorage 要求。宿主预览不执行生成 Python／Node。

机制测试不能代替真实探针。成功 profile 须绑定本次镜像、SandboxRuntime／Runner／镜像控制配置指纹与必要探针结果；变更后失效。通过隔离和集成验证后才解除新模式门禁；本设计不授权新的真实模型预算。

## 实施顺序与现状

本接口增量已确认，按复用现有 Runner 实现统一模块 → 真实合成探针 → 接入验证和预览／完成集成验证 → 更新证据及启用状态推进。连续主会话、任务范围写权限和真实缺陷成本验证沿原后续阶段推进。
