# 开发Token上涨逐轮诊断

## 结论与范围

只读核对上一轮双缺陷10次开发请求与本轮单缺陷13次请求、供应商usage、完整思考、工具响应和源码。零模型调用、未改执行机制。原runtime指纹保持，计算报告位于 `workspace/experiments/material-task-detail-no-review-20261009/cost-diagnosis.json`。

开发成本上涨是调用次数和每次输入增大共同造成的；记录能确认宽泛搜索、测试调查、修改延后及通过后调查，不能证明主要由模型随机性造成，也不能用不同任务推断取消审查的因果效果。

开发增量199,944Token，其中输入增196,288，输出增3,656。约80.9％增量发生在首次通过之前及该轮，并非主要在收尾。按上轮平均输入做纯算术分解：额外3次贡献57,572.4输入Token，其余138,715.6来自平均输入变大。此约29.3％／70.7％分解依赖基准选择，不是因果估计。

上轮审查另53,111Token，不能混入开发均值。两轮总量249,583→396,416增58.8％，但输入任务、失败自测次数及行为轨迹不同，不归因于取消审查。

## 每轮内容与判断依据

第一请求输入4,950与4,956Token，初始负载接近；第二请求变为10,111与16,068Token，差距在首轮工具结果后出现。本轮首轮以 materialIds 和「关联素材」全域搜索，两个结果50＋50命中、合计25,202字符，涉及文档、测试、验证脚本、代码和目标台账。上轮直接读两个业务模块，工具结果15,755字符。字符统计用于定位内容，不冒充供应商Token。

本轮第3次请求的实际思考已明确硬编码空数组为原因及 getMaterialIds 修法；随后确认接口／视图是合理调查，但第4轮就开始追查来源选题缺失占位，之后继续读测试夹具和大段UI断言，到第7轮才自测、第9轮才修改。第6轮一次UI测试读取705—1020行，虽请求316行，工具实际返回受既有200行上限限制；不是无界全文。第10次请求输入48,966Token，含历史工具正文98,430字符、历史思考13,800字符。上轮首次通过时输入26,454Token，历史工具正文55,609字符。

本轮失败自测后事实evidence只有命令、版本哈希、通过状态和result_ref，4,566字符；测试result和failure_details正文已省略，tool_failures亦用协议引用。原工具消息提供摘要8,437字符。这证明既有去重生效，不是旧全量失败输出重复注入；版本前后哈希仍有重复，但不是此次主要已确认差距。保留必要思考和工具协议本身不是bug，不能随意删除。

通过后发生上下文接力，第11轮原历史不再直接携带，而以已读范围50,064字符及自测事实恢复；上轮相应已读范围44,731字符。模型随后再次确认接口与装配，又调查已在前阶段关注的缺失占位差异，第13轮保存计划并提交。必要装配核查与无关边界调查不能全算浪费，但实际记录显示已知原因没有及时转成修改，接力后对已核对内容的判断连续性也不足。可选findings仅最后提交轮才保存，接力前没有模型调查结论可恢复；这不是程序丢弃已保存结论。

## 工具限制与后续建议（尚未授权实施）

`backend/app/runtime/repair_search.py` 的 search 只有query、cursor、version，遍历全部授权文件；有50条及字节上限，却不能限定文件／目录。因此第11轮即使描述明确检查topics接口，仍只能做全域关键词搜索。当前提示词要求聚焦调查，但工具缺少与之对应的范围能力，这是明确的机制限制。

建议优先为搜索增加可选文件／目录范围，默认全域保持兼容；范围只允许已有授权文件，分页版本绑定范围，不改变完整文件读取权限。验证应覆盖全域旧行为、范围内命中、越权／路径逃逸拒绝、范围变化或文件变化后旧游标拒绝，再对原宽泛查询做零模型离线投影。先证明减少实际命中正文且保留所需证据，不能立即宣称Token或成功率收益。

第二项建议是让模型在接力前可记录已有根因、已确认接口及剩余问题，沿用现有可选工作进度，不新增总结模型或强制计划调用；是否确实改善提交需后续独立验证。不要再用一条「少调查、快提交」提示词代替具体工具能力，也不要裁掉历史思考、只携带修改文件、强制自测通过即提交或重新加审查。本轮不实施这些建议、不付费重跑。
