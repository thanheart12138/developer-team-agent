# 返修上下文与替换恢复门禁修正

## 授权与范围

用户在 20 次真实返修实验后确认两项修正：减少每轮重复附带产品全文，让 `replace` 能在无写入诊断门禁触发后恢复进展。先更新 Dev Design，再修改 Worker 和直接相关回归；不追加真实模型调用，不续跑旧任务。

## 修改与验证

- 有 `unit_file_scope` 的单元／切片请求只自动刷新文件清单与哈希，不附带范围内全部正文；必要正文由 `read` 提供。原始目标、失败、自测信息、读结果及 DeepSeek 协议要求的工具历史保留。旧显式全文快照入口保留原行为。
- 重复读取门禁核对当前请求实际是否保留相同版本、相同范围内容。即使历史曾读过，正文已经省略时仍允许补读；版本变化和新范围同样可读。不允许在仍有可用正文时无意义重复读。
- 无写入诊断阈值达到后，`write` 和 `replace` 都可执行。成功替换重置计数；失败替换后新的诊断仍被阻止，相同动作与调用上限未取消。

直接相关回归 147 项通过；最终 `.venv/bin/python -m pytest -q --disable-warnings` 为 239 项通过、4021 条现有弃用警告；`git diff --check` 通过。覆盖无需自动全文也能按需读取依赖、哈希随修改刷新、已省略正文可补读、仍保留正文不可重复读、五次诊断后成功替换恢复额度、失败替换不能恢复额度。

离线回放上次真实第 2 次请求的 context：旧 289,586 字符，新 28,034 字符，减少约 90.3％；原始未闭合目标内容保持一致。测量使用隔离产物当前清单与同一上下文结构，只核对请求字段体积；文件内容在此前真实实验中已经变化，不是新旧模型实测成本对照。原始测量在 `/private/tmp/repair-objective-context-fix-measurement-20260930.json`。

正式库只读检查 0 待处理事件／0 运行中任务后，停止 Worker 11599，启动 Worker 17321，确认进程存活。未改正式任务状态、数据库 schema 或密钥。

两项机制修复已验证并加载服务，未进行新的真实 DeepSeek 调用。90.3％是一次 context 字符体积减少，不能直接解释为总 Token 或费用减少：按需读取和 DeepSeek 完整思考工具历史仍有成本。模型能否及时交接、真实审查能否关闭原始目标及完整流程成功率待验证。
