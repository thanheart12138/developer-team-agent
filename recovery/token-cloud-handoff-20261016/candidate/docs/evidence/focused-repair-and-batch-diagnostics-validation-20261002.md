## 当前实现

- 切片返修用 `repair_task` 提供当前失败引用、系统执行契约引用、原目标引用、固定测试清单及既有写权限引用。完整卡片保存到 `evidence/slice-repair-card-{run.id}.json`，内容保持，不再自动重复发送所有接口、验收及验收映射。内部行为标准保留只读引用；从零开发仍发送正式执行卡。
- 原卡与标准可通过现有受控 read 获取，模型不能修改这些证据。原始目标与原集成失败报告仍随返修上下文提供，未通过摘要推断或降低业务验收。
- 每批工具动作执行完后刷新真实诊断，两处修改之间不插入测试。固定命令及全范围版本相同则复用，各版本报告分别留存为 `evidence/slice-repair-diagnostic-{run.id}-{version_key}.json`；恢复或回到已测版本不再次运行程序测试。
- 同批主动 `run_unit_tests` 的真实同版本结果直接复用，不额外执行一次程序诊断。程序诊断不设置开发自测资格，不自动提交或结束；诊断通过后仍允许继续修改，提交仍需当前版本主动自测通过。
- 当前自测优先；自测过期后，新的当前诊断优先展示。旧自测与旧报告保留版本状态，不用过期通过结果提示提交。
- 激活 Developer v12，旧 v11 保留；未改变 DeepSeek thinking 参数、调用预算或写入范围。

## 复现与定向验证

先补回归并运行五个相关用例，原实现全部失败：旧卡仍在首轮输入、回到已测版本仍重复测试、修改后下一轮仍无新诊断，以及两种过期自测遮住当前诊断的情况。修复后执行：

```sh
.venv/bin/python -m pytest -q tests/test_slice_workflow.py tests/test_worker_events.py tests/test_unit_workflow.py tests/test_tool_summaries.py tests/test_prompt_registry.py --disable-warnings --tb=short
```

结果：193 项通过，30.07 秒；差异格式检查通过。关键证据：

1. 首次真实 Node 失败进入返修请求；没有整卡和整批标准正文，完整原卡可读且不可写，原集成失败仍保留。
2. 同版本恢复复用；改变文件会产生新的失败诊断，回到先前已测版本复用其原报告。
3. 实际 Worker 循环＋Fake 模型动作＋真实 Node：一批修改两文件后只诊断一次，读取与无效提交不重测。诊断通过后无主动自测的提交被拒绝，模型还能继续修改并收到新的失败；修复加主动自测后不再重复诊断，最终真实显式提交后仍执行独立测试。六个模型批次，共三次程序诊断及一次主动自测，后续独立测试另计。
4. 当前诊断分别为通过／失败时，都不会被过期的旧通过自测遮住；诊断通过仍提示主动自测，不能建议直接提交。

这些证明机制与真实工具行为，Fake 模型不能证明 DeepSeek 能自行采取上述动作，也不能证明生成软件满足完整产品要求。
