# 受控搜索与有效上下文：第三批验证

## 结论与范围

2026-10-09，按用户确认及「搞吧／继续」实施。新 repair-v1 主会话增加任务授权范围字面搜索、默认 200 行读取、实际可见范围去重与稳定接力记录。机制及真实工具合成链路通过；执行模型与独立审查仍为固定响应，没有真实模型实验，不证明实际 Token 收益或成功率提高。

全套回归 399 项通过，34.57 秒；随后默认预览去重及合法新版本补读修正，最终相关 53 项通过，1.53 秒。最终补充用例未重跑整个全套，范围如实区分。面试讲解、文档索引和原架构问题同步。

## 实现与实际读取规则

- `repair_search.py`：仅扫描当前可读清单中的产品、批准文档、原目标及明确失败引用；不运行 shell／regex。每页最多 50 条，片段最多 400 字符，整体结果受 100 KiB 限制；二进制／非 UTF-8 文件明确跳过，跳过清单也限长。查询与文件集合哈希绑定分页，版本变化不能续旧游标。
- `RepairTools._read`：默认 200 行，显式范围继续读取；保留当前 SHA-256、实际返回行号、总行数与截断标识。搜索片段不证明完整行，更不证明全文。
- 去重：仅依当前请求中的真实正文和当前文件版本；合并相邻可见范围。重复默认预览会被拒绝，未覆盖、已省略或新版本正文允许补读。合法补读不再被旧动作签名次数阻止，非法参数仍受工具与循环门禁约束。
- 原检查点就是读取登记依据，继续保留全部动作、参数、实际输出和哈希，没有建立另一份相互竞争的文件知识账本。

## 接力及协议边界

复用已有 DeepSeekContextRelay，主会话接力路径以原 Event 与 history_key 固定，不跟随阶段 Run 变化。只有实际写入改变产品、模型主动全量自测结果对应当前版本、完整工具批次结果均落盘时才能建立边界；不额外运行自动诊断，也不自动提交。

新的是独立模型对话上下文，逻辑任务 session、原始检查点、Trace、原目标与预算保持。新上下文携带当前计划／决定、有效失败、自测状态及已知范围的当前正文；边界之后的完整思考和 tool 配对续传。无工具响应的思考也必须保存／恢复，普通「完成」文本继续要求明确提交。

官方明确要求带 tools 的后续请求回传完整 reasoning_content，不能在同一对话中随意删除。已通过公开网页实际读取核对：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/) 。公开网页留存于实验目录 `deepseek-thinking-mode-20261009.html`，不含认证；独立上下文的真实供应商兼容和收敛仍未新测，不能用序列化回归代替真实 API 证据。

## 本轮发现与修复

1. 第三批核对发现第二批普通结束文本分支仍引用旧 owned_files／局部 file_hashes，主会话可能报错。修复为任务版本字段，并新增无工具思考中断恢复回归。
2. 默认预览被当成全文请求时，重复读取仍可能获准。明确默认 200 行语义，登记实际覆盖；未读部分通过显式范围继续。
3. 旧相同动作次数可能在版本变化后拦截合法读取。主会话有效补读改由实际可见正文／版本判断，不放宽越界和非法参数。
4. 对接力尾部做索引判断，避免只为判断是否修改而再次刷新源码正文。失败与已有历史保留，不为通过测试削弱交付门禁。
