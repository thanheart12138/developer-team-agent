## 状态

## 改动与依据

- `repair_session.py`：任务级逻辑 session 和检查点，不按旧卡片选写权限。主会话固定 Provider、模型及提示词指纹；受控 plan／decision 状态与原始测试基线保存在程序记录中。
- `worker.py`：显式 repair_request 保存原目标后直接进入执行；新模式自测／提交仍经过 sandbox。阶段失败回原会话，完整思考、call_id 和工具结果保留；完整工具批次意图未确认时停止，不重放副作用。
- `repair_runtime.py`：全产品集合变化使旧自测／提交失效；独立验证失败设置会话恢复边界，禁止复用该次失败提交，保留原始协议。提交保留相对原测试的 Diff。
- `repair_objectives.py`：独立审查收到原始目标、真实浏览器证据及测试 Diff。该机制不能形式化证明模型没有弱化断言。
- API／前端：等待决定显示具体问题、影响及提议，回答绑定 decision_id。回答不自动更新正式设计、增加预算或授权产品大改动。

保护范围：只允许当前任务 product 中普通实现／测试和相关新增文件；禁止正式文档、审计、其他任务、凭据、治理文件及链接／特殊文件。固定全量 `node --test`，不让模型选择绿灯子集。自测通过后仍允许必要阅读和修改，只有明确提交才开始冻结验证。
