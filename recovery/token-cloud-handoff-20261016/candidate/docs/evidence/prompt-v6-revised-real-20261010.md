## 与原v6比较

同故障跨文件原v6第8次才修改，没有主动自测；修订版第7次修改、第8次自测通过，但两者都未提交。Token从131,584到134,749，上升2.41％，耗时25.2到32.7秒，不能认定成本收益。

本次第4次思考已明确编辑应从get改update；接着读取脚本、查helper和编辑测试，第6次仍检查测试辅助函数，思考中也称该检查并非严格必要。充分修法后的调查延迟仍存在。第8次对历史读取的旧hash与最新manifest有疑惑，读取发生在修改前，manifest发生在修改后；ToolRuntime范围read返回的是全文文件hash，不是片段hash，没有证据证明工具哈希错误。本轮不据模型疑惑修改工具。

业务决策从「首批搜索，后续未验证」变为「首调用实际成功请求决策」，是有效路径证据。但新测试使用连续Worker与显式冲突反馈，旧测试是首响应探针，输入和入口不同；不能把全部改善及Token差异单独归因于提示词。
