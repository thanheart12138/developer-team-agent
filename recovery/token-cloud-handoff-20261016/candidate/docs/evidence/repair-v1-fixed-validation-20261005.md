## 实现

- `repair_runtime.py`：程序状态先原子保存，再投影 Task；每个显式提交不可覆盖，冻结完整产品、有效需求／验收标准和授权版本。
- 固定顺序：全量 Node、程序托管 HTTP、浏览器、独立原目标审查、待用户验收。无阶段 Planner／finish 请求；浏览器阶段不重复执行已通过的 Node。
- 旧卡写权限与自测／显式提交复用，提交后拒写。产品失败回现有开发入口；连续 session 和任务级写权限尚未实现。第一批的提交接入点为当前逐切片返修，旧单模块／逐单元任务仍保留原流程，不宣称已全部接入新提交入口。
- Provider `client.stream` 前登记保守尝试，失败和重试计数不回减；审查使用已授权预留。`BudgetExceeded` 原样穿过 Worker，无重试／降级／传输包装。旧任务不创建新预算。
- API 返回可选执行信息及任务版本；新验收绑定当前 submission 与版本。运行隔离未决定，真实新事件无法进入执行。

## 复现与期望

命令：`.venv/bin/python -m pytest -q tests/test_repair_runtime.py --disable-warnings`。

测试使用内存 SQLite 与 pytest 临时产品，固定 Node 用例、独立静态服务以及已安装 Chrome。外部 Provider 在传输边界被夹具替换，独立目标审查仅使用固定响应，不发送真实请求。

| 场景 | 期望及实际 |
|---|---|
| 自测而无提交 | 不进入测试，符合 |
| 显式提交后再写 | 工具拒绝，符合 |
| 新增、删除、非代码文件、需求或授权变化 | 旧提交失效，符合 |
| 测试执行时外部修改 | 结果无效并停止，符合 |
| Node 零测试／skip／todo | 不推进，回开发，符合 |
| 命令不可用／执行环境故障 | 明确停止，不引导产品返修，符合 |
| 实际发送失败后重试 | 每次预约计数；耗尽后不进入 stream，符合 |
| 审查预留／重新读取状态 | 执行不可占预留，恢复不清零，符合 |
| 同 Event 恢复／新尝试历史计数错误 | 保留尝试／拒绝回减，符合 |
| 已存阶段结果但数据库旧阶段 | 不重跑已存阶段，补投影，符合 |
| 未完成的命令 intent | unknown_side_effect 停止，不重放，符合 |
| 真实 Node＋HTTP＋Chrome | 同一冻结合成版本完成固定流水线，符合 |
| 独立目标未覆盖 | 原始反馈保持且回开发，符合 |
| 陈旧验收 | 拒绝；当前版本明确验收后才 succeeded，符合 |
| 未选隔离／旧任务 | 新入口拒绝，旧模式不迁移，符合 |
