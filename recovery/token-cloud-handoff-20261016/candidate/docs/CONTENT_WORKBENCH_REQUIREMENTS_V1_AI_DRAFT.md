# 本地选题与内容生产管理工具：需求草案 v1

用户明确委托 AI 撰写并保存。用于下一次多模块基准测试；不替代模拟器自身的产品需求、架构和 Dev Design。技术选择与运行约束尚待确认。

## 要做什么

开发一个单用户、在本地浏览器使用的内容管理工具，串联「保存素材 → 整理选题 → 创建内容任务 → 推进生产」的完整流程。

包含四个模块：

| 模块 | 当前版本功能 |
|---|---|
| 素材库 | 新增、查看、编辑和删除素材；每条素材包含标题、可选来源链接和笔记；按标题与笔记关键词检索 |
| 选题管理 | 新增、查看、编辑和删除选题；每个选题包含标题、内容角度和优先级；可以关联、解除关联多条素材 |
| 内容任务 | 从选题创建内容任务；编辑任务标题、草稿和可选截止日期；在「待写作」「写作中」「待发布」「已发布」之间手动切换 |
| 工作台 | 展示未完成任务、逾期任务和各状态任务数量；点击任务进入详情 |

### 跨模块行为

- 一个素材可以关联多个选题，一个选题可以关联多个素材。
- 删除已关联的素材时，先提示影响；确认后删除素材及关联，保留选题。
- 一个选题最多创建一个内容任务，重复操作进入已有任务。
- 创建任务时复制选题标题作为任务标题；之后两者可以独立编辑。
- 内容任务可以查看来源选题及该选题当前关联的素材。
- 已创建任务的选题暂不允许删除，界面说明原因。
- 工作台根据内容任务的当前数据更新；「已发布」任务不算待办或逾期。
- 截止日期早于本地当天、且尚未发布的任务算逾期。
- 数据在刷新页面和重启本地服务后保留。

### 当前边界

- 不需要登录、多人协作、云同步或公网访问。
- 来源链接只用于保存和打开，不自动抓取网页。
- 草稿使用纯文本，不做富文本编辑器。
- 不包含附件、AI 生成内容、自动发布和通知。
- 页面布局与视觉细节可以采用简单默认值，不得增加上述范围以外的业务功能。

## 为什么要做

第一目标是检验 AI Agent 能否在需求与设计确认后，无需人工补代码，完成一个具有多个业务模块的软件。

重点检验：

- 能否按职责划分模块，并通过明确接口协作。
- 能否正确维护跨模块引用、状态和持久化数据。
- 能否验证完整用户流程及错误操作后的恢复。
- 能否在后续跨模块需求变更中保留已有功能。

第二目标是得到一个可以自用的轻量内容管理工具。

## 怎么算成功

### 一、完整流程通过

在实际启动的软件中完成以下操作：

1. 新建三条素材，通过关键词找到其中一条并修改笔记。
2. 新建两个选题，让同一素材被两个选题关联。
3. 从其中一个选题创建内容任务，再次点击创建时进入同一任务。
4. 编辑草稿、设置截止日期，将任务推进到「写作中」。
5. 在工作台看到正确的任务、状态数量和逾期结果，并进入对应任务。
6. 删除一条已关联素材，确认影响后，选题与任务仍可正常查看，已删除素材的关联消失。
7. 刷新页面并重启服务，确认数据、状态和关联关系保留。
8. 将任务改为「已发布」，确认其从待办和逾期列表移除。

### 二、边界操作通过

- 素材、选题和任务标题不能为空；保存失败时保留已填写内容，修正后可以正常保存。
- 取消删除不改变数据。
- 删除已有任务的来源选题时被阻止，其他功能仍可正常使用。
- 编辑任务标题不修改来源选题标题。
- 一个模块的操作不能破坏其他模块无关的数据。

### 三、多模块实现可复核

- 素材、选题、内容任务和工作台的职责在代码中有明确边界。
- 跨模块的数据访问与操作遵守确认后的架构及接口设计。
- 不能仅靠拆分文件或增加页面数量宣称实现了多模块。
- 保留自动测试和真实浏览器操作证据。

### 四、Agent 独立完成

需求、架构与 Dev Design 确认后，Agent 在明确的调用预算和执行范围内完成开发、测试、启动及浏览器验证，不需要人工修改生成代码。

若执行期间发现关键设计缺口，必须明确记录；需要人工补决定的这一轮，不计为完全无干预完成。最终验收仍由用户确认。

这份草案只定义产品需求。持久化方式、技术栈、模块接口及错误处理机制留到架构和 Dev Design 阶段决定；实施前需要修订现有「单模块」约束。
