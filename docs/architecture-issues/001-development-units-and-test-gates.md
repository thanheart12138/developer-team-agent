# 001：从整体开发转向模块／功能开发与测试门禁

日期：2026-09-17。状态：机制已实现并验证，完整真实自主流程未通过，用户本人验收未执行。

## 问题与目标

原开发方式以整份 Dev Design 和整体产品文件推进。增量修复可能携带大量代码与测试；需求变大时，架构／设计文档也会变长。真实 DeepSeek 运行出现长输出截断，另一次运行生成部分文件后反复读取。这些现象不能仅凭一次失败证明任务规模是唯一原因，但说明原整体开发方式缺乏可验证的中间交付边界。

用户提出并确认：架构先划分模块，较大模块拆功能，每个单元有独立 Dev Design，定义交互；完成可测试模块／功能后立即测试，真实结果反馈开发修复。

目标是控制每轮设计与开发的范围，并用程序测试决定是否可以推进，而不是只靠模型宣称完成。

## 解决过程

1. 保留单 Worker 和七阶段流程，不因拆模块直接引入多 Agent 或新数据库表。
2. 架构产出版本化开发计划，定义模块职责、接口、单元依赖、文件所有权和测试交付物；校验唯一所有权、无环依赖及非空测试。
3. 先评审共享契约，再逐单元生成并评审独立 Dev Design；根设计只作为索引，避免每次拼接所有设计。
4. 开发只能写当前单元文件，依赖只读；当前单元及直接依赖实现快照每轮刷新，其余依赖按需读取。
5. 程序执行当前及已完成单元测试，失败反馈真实命令、输出、要求及文件版本。最多三次开发／测试尝试，不能弱化预期来通过。
6. 用设计与文件哈希判断是否可以恢复既有通过记录；设计缺口回设计阶段，全部单元通过后仍有集成测试、启动、浏览器验证和人工验收。

首轮真实计划曾产生不可测试单元；修正输入说明与校验反馈后，又遇到跨单元测试方案冲突。后续整模块／功能混排和非法 ID 仍导致计划失败。这里记录的是「模型计划如何由程序约束」的架构边界，不将每次提示词调整作为单独问题。

## 方案取舍

| 方案 | 收益 | 代价与决定 |
|---|---|---|
| 整体设计、整体开发后测试 | 流程简单，适合小任务 | 大任务上下文和失败定位范围大，用户决定增加单元边界 |
| 每个文件一个开发单元 | 单次输入小 | 文件未必能独立测试，容易形成无意义单元，不采用为默认规则 |
| 按模块／可测试功能串行推进 | 职责、文件归属和依赖明确，支持中间验证 | 要处理跨单元契约、缓存失效和集成返修，用户确认采用 |
| 多 Agent 并行开发 | 可能减少耗时 | 增加共享状态与冲突处理，当前目标不需要，未实施／未测试 |

局部通过不能代替整体行为正确，因此保留最终集成与浏览器门禁。文件存在也不能当成实现完成。

用户确认的模块／功能串行方案已实现，固定设计下真实开发可完成；全自动架构、全部单元设计、开发、返修和交付的连续链路仍未通过。保留旧单份设计任务入口，不自动转换历史任务。

## 2026-09-18：从零流程暴露公共入口装配与文件归属冲突

用户要求从头复测，并澄清每轮独立 300 次机会。从初始合成需求开始，系统生成产品、架构、math／ui 两模块及四个功能单元、共享契约和 Dev Design，没有复用产品代码或预置设计。测试控制核对产品候选并通过审批，另对 URL 来源提供 Worker 代码已实现的事实后同轮恢复，因此不称为完全无人干预。

加法真实自测 9 项通过并提交；平方自测失败，公共入口 index.js 缺 squareSum 导出。计划把 index.js 唯一归 math_add，平方只有 square-sum.js 和测试的写权限；共享契约要求经该入口导出，单元设计把导出交给「其他单元」，没有明确可执行的装配职责。模型尝试写依赖被拒，随后说明 BLOCKED，但未按约定以标志开头，程序未回设计，最终有界停止。代码细节及 Trace 见本轮完整证据。

这不是单纯 Node 测试 bug，也不能靠让开发越权或改测试绕过。问题属于单元划分、公共接口装配职责与文件所有权的一致性；结构校验能验证 ID、文件唯一归属和 DAG，尚未证明生成的职责能在该 DAG 与权限内实施。自测揭露了缺口，未自动修复上游设计。关于阻塞传递的附加问题同步记录于 004。

建议（开发助手提出、未实施）：先在设计层明确由谁在何时拥有并装配公共入口，核对各单元交付后是否能仅凭当前及前置文件完成验收，再确认实现。候选取舍包括后置公共入口装配职责，或调整模块／功能划分避免公共入口需要后续单元修改；不能直接允许共享写入破坏唯一所有权。避免只增加一句提示而不验证计划、契约和单元设计能否共同实施。

本轮实际 50 次／598,317 Token，含入口旧探针预写产品的 4 次；主空工作区流程 46 次／583,379 Token。未到预算上限，尚未进入 UI、启动及浏览器验证，没有扩大正式权限或手工补代码。新验证报告保留入口修正、澄清恢复与失败成本，不把旧固定设计成功写成自主设计成功。

### 上下文证据与遗漏

最终共享契约 5,554 字符，加法设计 4,909，平方设计 7,394，输入校验设计 4,572，UI 交互设计 10,130；五份共 32,559 字符，不包括产品、架构及修订历史。这里是 Unicode 字符统计，不是 Token。

sent-022 的 dependency_designs 携带三份直接依赖设计全文，JSON 序列化约 17,452 字符；shared_contract 约 5,755，approved_product 约 3,149。它们在 022—030 的作者和评审请求中反复携带。单次输入从首稿 17,518 Token 到评审最高 25,093 Token。unit_workflow.py handle_design 明确读取直接依赖完整设计，而不只是公共接口；因此“仅直接依赖”并不意味着上下文很小。完整文档反复发送、反复生成与修订调用叠加，是已证实的成本来源；字段级字符占比不能换算为字段级 Token 贡献或必然节省比例。

设计上下文 project_constraints 仅列本地 HTTP、Python Playwright 等六条约束，没有说明 Worker 将 result_url 作为 argv[1]。worker.py 的开发指令却明确该调用契约，实际 verify 命令也传入 URL。设计阶段缺少现有运行事实，后续靠测试控制问答补齐；不是需要用户新作产品决定。把事实作为唯一受控运行契约共享，是替代不一致输入，不是继续增加提醒。

### 为什么评审通过仍然不可实施

计划将 index.js 唯一归 math_add；math_square_sum 只拥有 square-sum.js 和测试。共享契约要求测试及 UI 从 index.js 导入 squareSum；加法设计明确只负责 add，把 squareSum 交其他单元，同时不引用内部子文件；平方设计要求入口 re-export，却无权修改入口。依赖顺序要求加法先完成，后续平方不能回写。结构上文件唯一、DAG 无环，职责上却没有能完成该装配的人。

共享契约、加法、平方的 Reviewer 均返回 ready。共享契约评审能看到计划；平方评审能看到当前文件归属和加法依赖设计，因此不能把漏检全部归因未提供上下文。评审判断没有形成“哪个单元在何时、以何种权限使公共接口可用”的一致结论。程序 ordered_units 检查结构，不证明这些自然语言职责可共同实施。

额外静态发现：平方设计写 square-sum.js → index.js，并要求 index.js re-export square-sum.js，却声称无循环；落实后会形成文件级循环引用。ESM 循环不必然运行失败，本次未实施也未验证，但这说明模块／单元 DAG 无环不能替代文件依赖检查。无须为此新增评审层。

### 收敛建议与待确认取舍

建议先保留 math、ui 职责边界，将四个功能开发单元合并为 math、ui 两个可验收单元；公共入口与内部实现由同一单元负责。合并开发粒度不合并业务模块。当前任务很小，增加后置装配单元会再引入设计、上下文和交接，故不作为首选；复杂任务是否再拆，待真实任务证明必要。

保留隔离、调用上限、真实自测及版本绑定、显式提交、独立验证、最终浏览器与人工验收。保留现有执行账本和有界停止，暂不再改摘要策略。压缩为一份简短共享契约和各单元必要差异，依赖上下文以接口／约束为主；不在每份设计复制共同测试规则、产品全文和依赖内部设计。先减少单元及重复内容，不同时拆除全部已有评审，便于判断变化来源。

运行事实统一来源；阻塞作为结构化控制结果交回既有等待／设计路径，替代易受前言影响的文本前缀判断，不新增 Reviewer、诊断 Agent 或泛化工具。不建议只改为全文搜索 BLOCKED，因为引用和否定语句可能误判。具体协议由用户确认设计后再实施。

停止增加提示、评审层、历史查询工具、细分单元和调用预算；不靠开放跨单元任意写入解决规划矛盾。以上均为开发助手候选方案，未确认、未实施、未验证收益。

### 真实验证方法

用户确认方案并授权实现后，以同一初始需求、同一模型配置、真正空工作区验证；保持两模块及独立测试的产品要求，显式记录允许开发粒度变化，不能偷偷删去架构要求。每轮独立最多 300 次实际 HTTP（含重试），正式单 Step 100 次不变。预先固定正常、边界和错误恢复验收，固定产品审批方式；运行事实应事先提供，运行中测试控制补事实、改代码、改设计或代提交均单列介入，不能称自主完成。

同时报告完整交付结果、输入／输出／总 Token、各阶段逻辑调用和实际 HTTP、测试控制介入次数与内容。失败和入口错误成本保留，截断／重试单列。先验证完整交付，再讨论成本收益；单次成功不能证明稳定率，需用户另行授权重复轮次。固定夹具 65,591 Token 与本轮 598,317 Token 起点不同，不计算退化或节省比例。本次只完成证据审计，没有真实重跑。
