# 面试演示指南

当前固定案例：素材删除后跨多个选题清理关联，任务详情显示剩余素材。真实DeepSeek已完成13HTTP／396,608Token的返修，原断言独立Node150项及Chromium60条通过，系统待用户验收。不是从零生成整站演示，也不宣称稳定成功率。

## １．入口与现场启动

当前演示：http://127.0.0.1:51881/ 。这是已冻结产品的可信静态预览，无模型调用。浏览器首次打开是空业务数据，按下节建立合成样例。与原实验服务53953、正式API8001及前端5173分开。

从项目根目录只读核对原断点：

```bash
PYTHONPATH=. .venv/bin/python workspace/experiments/material-cross-module-repair-20261009/demo.py check
```

成功应显示awaiting_acceptance、http_attempts=13、http_cap=30、sqlite_read_only=true、task_resumed=false、model_http_calls=0。缺失／变更数据或迁移后旧路径不匹配时会报错，不能重新创建数据库或修改计数冒充恢复。

如果51881没有运行，再在一个终端启动静态演示：

```bash
PYTHONPATH=. .venv/bin/python workspace/experiments/material-cross-module-repair-20261009/demo.py serve --port 51881
```

保持终端运行；已有服务占用该端口时不要重复启动或终止不明进程。现场不执行run.py、preflight.py、prepare.py或build；不需要Docker、正式数据库、API密钥或付费请求来浏览已冻结成果。以上命令使用已安装的项目依赖，不安装新的包。

## ２．四分钟展示顺序

**第一分钟：说明问题和真实执行证据。** 原需求要求一个素材可关联多个选题。实验注入「只清理第一个选题关联」和「任务详情不装配素材」两个缺陷；绿色预检通过、故障红灯，再交给原系统真实DeepSeek修复。展示 [验证记录](evidence/material-cross-module-deepseek-real-20261009.md) 的13请求、150项／60条独立复测和待验收状态，说明没有人工改产品。

**第二分钟：通过页面建立样例。** 素材库新增「共同素材」和「保留素材」；选题管理新增「选题甲」「选题乙」，逐个编辑并勾选两个素材后保存。从每个选题创建内容任务，查看各自来源选题与两个关联素材。

**第三分钟：展示核心边界。** 素材库删除「共同素材」，先观察影响提示同时包含两个选题，点击取消，确认素材和关联仍在；再次删除并确认，两个选题和任务保留，各任务详情只显示「保留素材」。刷新浏览器，再从选题进入原任务，仍显示剩余素材，重复进入不增加任务数。

**第四分钟：解释系统设计和局限。** 连续会话选择相关文件；模型主动自测并显式提交；程序冻结全文件版本，固定执行Node／浏览器；该历史案例含独立目标审查，新返修已取消审查并等待用户验收。程序事实和模型判断分开；实际请求预算含失败和重试，不因接力／恢复重置。本例自测通过后仍5轮才提交，没有使用可选工作进度字段，因此交付通过但收尾优化尚不稳定。

素材删除和取消均为本地合成业务操作，不修改实验SQLite、原产品源文件或正式任务。想从空数据展示时使用新的无痕窗口，不清理真实用户数据。

## ４．恢复和已知边界

check只证明当前保存的数据库、工作区、检查点、提交和计数互相匹配；不会继续付费流程，也不能代替运行中崩溃恢复测试。整个目录迁移到另一父目录时，SQLite中的原workspace_path可能不再有效，需要明确恢复方案，不能自动改数据库。

本地持久目录和冻结演示仍可能因磁盘故障丢失，当前没有异地备份。代码、镜像或环境变化后，真实返修入口还需要重新核对sandbox profile；静态演示不能证明新环境支持真实执行。不同场景Token不能直接当成优化对照，真实任务仍有限范围。最终验收由用户负责。
