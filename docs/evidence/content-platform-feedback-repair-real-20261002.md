## 两项 Node 失败的具体原因

### 图标断言误匹配注释

`product.test.js:645` 对整个 HTML 使用 `/favicon\.ico/.test(html)` 并要求 false。模型新增的 HTML 注释恰好包含「不再请求缺失的 /favicon.ico」，因此实际 true、期望 false；真正的 `link[rel="icon"]` 指向内联 SVG，独立浏览器没有 favicon 404。

待修的是断言观察范围：应检查实际图标引用和请求，不能把注释当作资源引用。不能删除相关验证或隐藏 404 来通过。

### 消息调用记录仍采用旧预期

`src/tasks/tasks.test.js:747` 在成功保存后仍要求 spy 数组长度等于失败后的 1；新实现增加了一条明确的成功提示，实际为 2。该 spy 记录历史调用，而真实 `createUi.showMessage` 用 textContent 替换当前显示；独立页面确认旧错误已被成功提示替代。

待修的是对真实提示生命周期的断言：无效输入保护及错误提示仍必须验证，成功后应检查最后提示和实际保存结果，不能把历史调用数量当作当前错误是否残留。

两处缺陷已定位，本轮未由开发助手修测试。当前 E6-1 仍 open；E4-1 历史 closed 记录保留，但产品版本改变后旧核销证据需要原系统重新审查。
