# 原始验收目标保持验证

## 范围与依据

用户确认：从发现到修复保留原始期望行为和复现，最新脚本错误不能取代原始缺陷，其他测试成功不能替代目标验证。不重跑旧任务。

旧切片返修仅输入最新 `verification-report.md`，指令要求只修复该真实失败。脚本失败覆盖报告后，原始页面编辑缺陷没有独立的关闭条件。这是已核对的上下文缺口，不证明模型能力是唯一原因。

## 实现

- `repair_objectives.py` 按验收事件保存原始反馈、分类产生的期望／复现和当时报告。重复消费不覆盖原文，随后错误追加为阻塞。
- 普通开发与切片返修都收到未闭合目标。缺少结构化期望时保留用户原文，不编造需求；旧任务无法追溯恢复已经丢失的历史报告。
- 浏览器失败不调用目标审查。成功后由无工具写权限的独立模型调用核对原始目标与实际脚本，每项须引用真实存在的操作和断言。缺项、非法输出或伪造引用不关闭目标。
- 原始目标未闭合时不能进入待验收或通过 Bug 完成门禁。实际验证前后、审查期间的代码版本必须一致；产品或脚本改变后旧关闭证据失效。
- 仅存在待验证目标且普通验证通过时增加审查调用，同版本已关闭目标不重复审查。没有生成额外回归脚本。
