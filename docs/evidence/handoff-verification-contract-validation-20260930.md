# 显式交接门禁与验证契约对齐

## 决定与实现

用户确认：单元／切片取消叠加的五次非写动作门禁，保留重复读取、无进展与调用预算；向模型明确现行验证契约，允许修正旧卡／测试中的服务要求，保留业务断言。先更新 Dev Design，再修改实现。

- `worker.model_tool_loop` 对 `require_unit_submission=true` 不再执行五动作门禁；旧无显式交接流程继续保护。实际自测、提交版本校验、相同动作限制、无进展停止和总调用上限仍由现有代码执行，不强制替模型提交。
- Worker 统一提供 `verification_execution_contract`：Worker 管产品服务，verify_product.py 接收当前命令行位置 URL、只在该 URL 真正验证，不得自建服务、回退旧地址或跳过浏览器。Node 测试可启动临时服务作为 URL 夹具，不能要求验证脚本托管服务。
- 该契约进入切片 Planner 和单元／切片执行请求，并提升到执行系统指令中。旧卡内容不自动覆盖；允许在已有写权限内修正服务职责及日志文字匹配冲突，保留批准产品行为、实际操作与断言，不修改公共接口语义或降低验收。
- 激活 `slice-planner/v6`、`slice-developer/v9`，旧版本保留，注册表哈希匹配。
