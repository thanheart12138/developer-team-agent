# 返修当前事实与模型工作进度验证

日期：2026-10-09。用户明确要求实施。范围：仅新 repair-v1 上下文契约 v2，无新增真实模型 HTTP，无 schema／密钥／预算配置变更，未自动续跑任务或替用户验收。

## 实现及边界

- `repair_session.py` 从原 runtime 与完整检查点投影 `current_task_facts`：累计成功写入的类型明确调用引用、最后写入哈希与当前版本的关系、唯一自测状态、最新独立失败、决定、已知提交阻塞和提交后验证职责。最后写入匹配不证明所有历史操作或业务效果仍成立。
- 自测核对固定命令、全产品集合及字节、真实测试判定和 validation_boundary；失败保留详情，修改／命令改变为 stale，独立验证失败后边界前的绿灯不再可用。最新独立失败是当次验证事实，不从该失败猜测当前文件是否仍失败。
- `update_plan` 的 steps／reason 保持；新契约可选 findings／open_questions／next_action。完整计划替换之前计划，模型需要保留仍必要的工作线索；不自动从思考提炼、不强制额外调用。该计划绑定记录时产品／文档／授权 manifest，变更后 needs_review，仅为模型判断，不能自动审批、核销目标或清除失败。
- `worker.py` 仅对已绑定 v2 的会话在发送前投影，删除默认旧摘要和重复自测入口，保留当前实际正文、范围、查询结果、协议工具消息和完整原审计。未知批次继续停止，无自动提交。旧已绑定上一有效提示词的会话沿用 LEGACY_PROMPT、原 schema 与投影；更早已不匹配的提示词仍遵循原绑定错误，不隐式迁移。
- 原反馈在 input，原始验收目标保持原文与原状态。open 不能推定已实现或未实现。程序只描述已知门禁条件，完整提交检查仍由原工具实施。
