# 隔离实验持久留存修正与验证

日期：2026-10-03。授权：用户在确认正式系统已有持久化、问题属于隔离实验留存后回复「搞吧」。状态：已实现并完成本地机制验证；零真实模型调用，旧实验未恢复。

## 问题与范围

正式系统已有 MySQL 与项目 `workspace/{task_id}/`，现存目录中仍有历史产品、Trace 和检查点。此次修正只覆盖手动付费实验：两个入口默认在系统临时目录创建 SQLite／工作区，另外三个入口接受临时根目录；素材基准恢复若不传 `--prior-calls` 会从零计数，计算器还会在缺计数时尝试由逻辑 Trace 推测历史次数。单元返修夹具的源目录写死为历史 `/private/tmp` 路径。

先更新项目 AGENTS 和 `docs/README.md` 的目录约定，再修改入口。未改后端服务、正式库、schema、模型协议、提示词、产品要求或依赖，未启动 Docker／Worker，也没有重跑素材平台。

## 实现

- `tests/experiment_storage.py`：根目录统一为 `workspace/experiments/<experiment>/`；默认新建唯一目录，先写 README 与零计数。拒绝持久父目录自身、目录外路径、越界软链接和软链接父目录；显式新建不得复用非空旧目录。
- 恢复先核对已有 `test.db`、`workspace/` 和合法非负整数计数，再允许加载 Runtime；缺失／损坏就停止，不创建新库。无工具 Planner 没有检查点文件是合法情况，不要求每个 Run 都有检查点。
- 原库用 SQLite 只读连接执行 `PRAGMA quick_check`；损坏时在 Runtime 导入前拒绝，检查不创建库或修改原字节。任务语义与具体 Run 恢复仍由原控制脚本核对。
- `call-count.json` 在调用前刷新并原子替换，拒绝降低旧计数。素材基准恢复读取保存的次数，不再缺省零；计算器取消逻辑 Trace 条数回退。旧脚本原计数语义保持，计算器仍计 Runtime 调用，其他四个入口计实际模型 HTTP 尝试；不把计算器的 Runtime 次数称为含重试 HTTP 次数。
- 接入五个入口：计算器基准、素材基准、历史查询探针、历史续测、单元开发验证。历史续测拒绝把复制目标放进源目录，避免递归复制。独立诊断和返修夹具的源实验也先核对；`--verified-repair-probe` 新建须明确提供 `--verified-source`，恢复已有探针不重新复制源。
- 已建立本机 `workspace/experiments/README.md`，用 `git check-ignore` 确认由已有 `workspace/` 规则忽略；没有修改 `.gitignore`。后续临时控制脚本也按新约定留在跟踪的 `tests/` 或实验目录，不能只保存报告摘要。

## 本地验证

命令：`.venv/bin/python -m pytest tests/test_experiment_storage.py -q`。

首次二十项全部通过，随后针对软链接父目录／递归复制增加两项，针对旧固定来源增加三项，最后补只读 SQLite 完整性检查及一项损坏库回归；最终同一集合二十六项全部通过，数量相互包含，不相加，无失败。

七个修改／新增 Python 文件的语法检查与 `git diff --check` 通过。没有运行无关后端全套、生成软件或新的付费基准；合成计数七／八不是实际 HTTP 消耗。

文档链接核对初次未解码 `%20`，误判 README 中既有产品文档路径；修正核对脚本进行 URL 解码后，JSON、链接和标题一致性通过，没有修改旧产品链接。

- 本轮真实模型 HTTP／Token 都为零，不证明 DeepSeek／Kimi 已完成旧目标复审或 finish；旧最终结果和用量仍未确认。
