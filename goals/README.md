# 后续目标

## 目录约定

每个目标一份 `NNN-name.md`，写明目的、范围、依赖、完成条件、证据和权限边界。此目录保存可逐个启动的目标定义，`ROADMAP.md` 仍为真实进度源，设计以有效 Dev Design 为准。

最初委托仅建立目标；用户随后启动「依次做吧」，已推进001本地备份及恢复验证，用户随后决定仅保留本机一份备份，001—005已依次完成，006按原决定暂停。该目标不自动授权付费模型、迁移数据库或提交推送。后续用户指定目标后，依据文件建立 goal，先核对当前状态，再推进到完成条件；遇到关键设计缺口或红线操作按项目规则处理。调用预算在真实测试开始前确定，不能沿用已结束实验的剩余额度。

目标完成后同步本文件、目标文件和 ROADMAP，附可复核证据；验证、委托技术验收、用户批准分别记录。历史失败和成本不删改，不将建议当已确认设计。

## 执行顺序

2026-10-10 用户委托将「先建立提示词预期与评测，再统计阶段消耗、减少无效往返并守住完成率」拆成可执行目标。新增007—012已获实施授权：007—010机制实现并验证；008职责场景及完整离线正反身份审计已验证，待用户验收，011有限真实测试完成但目标仍有待办，012具体候选与对照预算待确认。每项要求交付实际可运行入口或页面、验证与证据；命令在入口实现后记录，不把规划命令冒充现有能力。大改动先确认对应设计，真实调用单独确认外发范围与总HTTP预算。
